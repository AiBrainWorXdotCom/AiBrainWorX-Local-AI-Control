# October 26, 2026: Activity and isolated-install verification

All dates here are Pacific time. This is an alpha validation record, not a claim
of a clean-machine install, universal hardware support or sustained model speed.

## Installation and isolation

A clean copy of the public Windows alpha.5 source archive was overlaid with this
version's changes in a separate source/runtime/workspace test tree. Setup used
existing working Python/Node, installed 617 official npm packages into the new
private prefix, completed its four stages and prepared separate client homes.
The isolated gateway health check and authenticated Harness page returned HTTP
200 on separate test ports. The original launcher configuration's SHA-256 stayed
unchanged. No global prerequisite was installed and no model weights were downloaded.

This verifies fresh client/runtime installation with existing prerequisites and
model files. It does **not** verify the full 58.4 GB model download, a new Windows
account or every prerequisite installer. Per-transfer progress, unknown totals,
stdin, exit codes and path redaction also have offline regression coverage.
Public screenshots show the real running workspace and Update Center. Process-screen captures stay private. Process names are masked in
capture mode; sample values are not substituted. No fixture output is presented
as a real model download.

## Resource monitoring

- Windows: an actual host-to-plugin process snapshot returned 20 CPU/RAM rows in
  1.391 seconds. Narrow fixed-field CIM queries run only on explicit refresh.
- Ubuntu WSL: the same host/plugin contract returned 20 CPU/RAM rows from real
  `/proc` inspection in 0.182 seconds.
- Hot disable, archive removal, disabled restoration, source-change approval and
  data preservation across source replacement passed using isolated state.
- Windows image captures and native Linux HTTP/frontend contracts verified the
  UI integration. GPU process allocation remains driver-dependent; no live GPU
  allocation acceptance result is claimed.

## Qwen monitoring smoke comparison

Hardware: RTX 3060 12 GB, Ryzen 5 5500, 32 GB RAM. Model:
**Qwen3.8-Flash-Next-GSQ-RCO-Coder-GGUF, IQ1_M**, through Strata application 0.2.4 / engine 0.1.48, the existing installed
Strata engine. No inference arguments were tuned or upgraded for this test.
Only one model engine was running; the test used a separate port/config and a
private copy of its expert profile, referencing existing weights.

After one warmup, six identical short Python coding prompts alternated light
monitoring off/on. Temperature 0, reasoning disabled, maximum 256 output tokens.
Every request reused 37 input tokens. These are warm cached repeats, not uncached
first requests or a sustained-performance benchmark.

| Run | Light monitor | Engine decode tokens/s | Output tokens | Finish |
| --- | --- | ---: | ---: | --- |
| 1 | Off | 31.8 | 243 | stop |
| 2 | On | 35.7 | 243 | stop |
| 3 | Off | 41.8 | 243 | stop |
| 4 | On | 45.1 | 243 | stop |
| 5 | Off | 46.0 | 256 | length |
| 6 | On | 44.5 | 243 | stop |

Light monitoring sampled existing `/metrics` and the real plugin about every
five seconds. Six sample operations took 0.193–0.212 seconds wall time each,
including HTTP/JSON and subprocess startup. Expensive process/GPU snapshots were
not part of this comparison. The small run showed no obvious generation stall;
it cannot establish zero overhead or a speed improvement. Cache warmup, variable
output and the truncated fifth reply prevent treating these as matched quality
results. No new public speed guarantee follows from these observations.

## Automated checks

Native Ubuntu WSL completed 135 Python tests without skips, including POSIX
ownership and lifecycle checks. The same Linux source passed nine Node frontend
contracts. Windows checks cover Python runtime contracts plus PowerShell 5.1
and 7 installer/UI/config-isolation contracts. Public-source privacy scanning and
syntax checks are required again on the staged release contents before commit.

Live Unreal/Blender acceptance, a native Linux model throughput benchmark and
large model redownload remain outside this verification. Existing Windows speed
measurements must not be relabeled as Linux results.
